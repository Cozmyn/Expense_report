# ADR 02 — Human-verified document intake

## Decisions

1. Use existing ReportAttachment as the immutable DocumentBundle. DocumentReview registers 1-based page ownership and the immutable first provider result. ExtractionAttempt records append-only raw versions; each includes OcrPage geometry/method/rotation and fields with word-derived provenance. DocumentGroup stores typed serialised SourceRegion/OcrField/OcrTax collections with an optional unique ExpenseId. This replaces the PDF's illustrative table names without losing lineage. Report revisions snapshot source groups. Schema releases 5 and 6 are additive and support SQLite tests and PostgreSQL deployment.
2. Use a local provider behind IDocumentExtractor: Extract/ExtractProgress, Health and Version. PDF text-layer extraction is deterministic; image OCR uses Tesseract TSV and auto orientation with installed ron/eng/osd models. If auto-orientation leaves critical fields unreadable, bounded ImageMagick PNG/JPEG rotation tries orthogonal alternatives with single-block OCR, retains each text attempt, and maps word boxes back to the unchanged original. Alternatives are ranked by detected fields, not a fabricated probability; human review remains mandatory. Rule-based segmentation groups consecutive printed pages only without conflicting identity signals. Geometric column splitting requires independent heading/total evidence on both sides. Ambiguity and missing fields remain for manual review. No external language model receives receipts.
3. Use same-origin signed upload, not public S3 URLs. Data Protection grants bind actor/report/document/file name/size/MIME/SHA and expire after 15 minutes. Completion returns 202 and starts the durable scan pipeline. A retained AwaitingCompletion document can be reauthorised by a current editor. Preview grants last five minutes and still require report authorization; no object key appears in original-document JSON.
4. Persist lifecycle events and dispatch jobs in the same database transaction. Deterministic event IDs and unique expense links prevent duplicated outcomes. Notice delivery uses event ID as its idempotency key. Job attempts are leased and bounded; failures preserve originals. Administrative OCR/scan retry creates a new job UUID and retains the previous failed job/attempts as Retried, with an immutable audit relation; it does not reset source-job history. Raw OCR belongs in scoped extraction history, never lifecycle metadata or diagnostic logs.
5. Suggestions are review aids, not approvals. Category names and optional ocrKeywords come from date-effective expenseTypes. Description comes only from labelled itemization. Cost centre/project defaults are resolved from controlled policy metadata and checked against active dimension versions. Employee identity, department, payment and card remain report-header data. Server financial validation remains authoritative.
6. One internal company per deployment. Report access is the authorization boundary. Multi-company hosting and external-model transmission require a separate approved design. No new OIDC/card-owner requirement is introduced.
7. Do not auto-learn tax/accounting policy from corrections. Corrections are durable training/evaluation evidence; future model changes require an approved corpus/version and regression results. No fake confidence: Tesseract scores are text recognition scores, text-layer confidence and heuristic boundary probability are unknown.

## Failure handling

Signature/length/hash mismatch rejects intake. Unsupported or malware-positive files never reach OCR. A scanner outage keeps quarantine and bounded retry. PDF page caps, command timeouts, limited render dimensions, temporary-volume and container memory/PID limits bound resource use. Malformed/encrypted PDFs keep a recoverable failure and manual replacement/review path. A failed page does not discard others. A retry cannot overwrite verified values or restore tombstoned groups.

Regrouping retains parent tombstones and immutable original attempts. Proposed values are rebuilt only from source fields inside the selected pages/regions; fields outside a new crop are not silently copied. Shared draft corrections are audited but stay unverified. Submission, Finance completion and accounting export invoke source completeness checks. Originals are archived with reason, not erased.

## Deployment and privacy boundary

Production requires PostgreSQL and private S3; S3 writes request AES256 server-side encryption. Configure encrypted database/object volumes, private bucket policy, TLS, least-privilege prefix access, region, backups, retention and legal holds in the target environment. Keep Data Protection keys durable and protected; rotating/removing them affects signed sessions and grants. Local unencrypted object storage is a development-only option. Application tests cannot certify cloud IAM, restore drills, legal retention or human Accounting approval.
