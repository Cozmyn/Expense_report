# PDF 02 security review and operations

Threats considered: IDOR across reports, forged upload/viewer grants, MIME spoofing, malware, oversized/decompression-heavy files, parser subprocess injection, malicious printed instructions, repeated jobs/consumers, concurrent edits, duplicated receipts, destruction of evidence and accidental disclosure of personal data.

Implemented controls: authenticated report scope on source/results/preview/history; actor-bound signed grants with expiries; CSRF and idempotency; actual signature/length/SHA checks; private original objects; clean scan gate; page/byte/process/render caps; non-root read-only/capability-dropped container with bounded temporary storage, memory and PIDs; generated subprocess paths with ArgumentList; no interpretation of source text as commands; no external OCR/model provider; immutable raw attempts, correction audits and event rows; unique one-expense source link; report version checks; worker leases and finite attempts; metadata-only outbox; protected preview raster, private/no-store and no object key in JSON. S3 writes request AES256 encryption; production local storage is prohibited.

Evidence lives in DocumentIntakeTests, OcrReviewTests, DocumentEventTests, corpus injection case, browser real-scan journeys, and the constrained container CI. This is a code threat review and regression record, not an independent penetration-test certificate.

Operational dashboard: /admin/health probes database/scanner/SMTP and actual PDF/Tesseract executable versions and trained language availability. /admin/ocr-metrics distinguishes review workload, quarantine and pending/failed work from quality. Per-report jobs expose attempt count, start/completion times and failure code. Document processing events retain their correlation job/attempt metadata; results remain in scoped raw history. A failed OCR operation leaves the original recoverable; Admin may retry a dead-letter job with reason. Employees and Finance may retry only through their current report edit rights.

Target deployment checklist: private bucket and access log; deny public ACL/policy; encryption enforced and keys managed; object versions/backups protected; application IAM restricted to required original prefixes; encrypted PostgreSQL volumes/backups and TLS; no raw receipts in telemetry; regional processing/retention/legal hold approved; restore drill; scanner signature updates and alarm; load test with the approved batch sizes; Data Protection key backup and access restrictions. Validate with real operators before production sign-off. Original archive is logical; physical deletion needs an approved retention/legal-hold policy.
